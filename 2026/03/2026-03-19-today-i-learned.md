# ☕ Spring Boot JVM 웜업

---

## 🔥 첫 번째 요청 비교 — 웜업의 핵심 가치

기동 직후 첫 요청에서 초기화 비용이 집중됩니다. 웜업은 이 구간을 보호합니다.

| 항목 | Warmup ON | Warmup OFF | 개선율 |
|------|----------:|-----------:|-------:|
| **Connection Acquire** | 8.170 ms | 24.128 ms | ↓ **66.1%** |
| **JPA Query** | 7.421 ms | 166.812 ms | ↓ **95.6%** 🚀 |
| **Jackson Serialize** | 0.769 ms | 92.203 ms | ↓ **99.2%** 🚀 |
| **Entity Metamodel** | 1.016 ms | 0.717 ms | ≈ 동등 |

### ⚠ Cold Start 합산 지연

| | JPA | Jackson | Connection | **합계** |
|--|----:|--------:|-----------:|--------:|
| **Warmup OFF** | 166.812 ms | 92.203 ms | 24.128 ms | **283.1 ms** |
| **Warmup ON** | 7.421 ms | 0.769 ms | 8.170 ms | **16.4 ms** |

> 실서비스에서 복잡한 쿼리와 대형 DTO 직렬화가 겹치면 이 초기화 비용이 곱으로 불어나고, HikariCP 타임아웃으로 이어지는 연쇄 장애 구조가 됩니다.

## 📊 정상 상태 (Steady State) 비교

> 💡 정상 상태에서는 ON/OFF 차이가 미미하거나 OFF가 근소하게 빠른 경우도 있습니다.
> 이는 측정 오차 수준의 차이이며, 웜업의 목적은 정상 상태 성능이 아닌 **cold start 보호**입니다.

## 핵심 결론

1. **웜업의 가치는 cold start 보호에 있다** — 첫 요청에서 JPA 95.6%, Jackson 99.2% 개선
2. **정상 상태에서는 차이 없음** — JIT 컴파일 이후 양쪽 모두 동일 수준으로 수렴
3. **실서비스 리스크** — 웜업 없이 기동 시 첫 요청 합산 283ms 지연, 복잡한 쿼리 환경에서는 수초 단위로 확대 → HikariCP 타임아웃 연쇄 장애 가능
